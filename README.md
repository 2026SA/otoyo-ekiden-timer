# 駅伝タイム計測アプリ 第1試作 v0.1

GitHub Pages でそのまま表示できる、駅伝大会用の第1試作です。

## 今回入れたもの
- トップ画面：管理者 / 計測係 / 参加者・閲覧者
- 管理者デモログイン（PIN: `1234`）
- CSVテンプレートのダウンロード / CSVプレビュー / 登録
- 15区間、同一人物の複数区間登録に対応
- 一斉スタート / 競技終了
- 計測係 A・B・C の3端末を想定した計測画面
- 同じチーム・同じ区間に対する複数計測値の保持
- 3人計測時：中央値を正式通過時刻として計算
- 2人計測時：平均を仮記録として計算し「要確認」扱い
- 1人計測時：その値を仮記録として「要確認」扱い
- 3人の値の最大差が0.5秒を超える場合も「要確認」
- 計測係による直前入力の取消
- 管理者による通過記録の削除
- 参加者画面：速報順位 + リアルタイムお知らせ
- 個人ラップ賞は参加者画面に出さない
- 結果CSV出力
- localStorageによるデモ動作（同一ブラウザ内）

## GitHub Pages へアップする方法
1. GitHubで新しいリポジトリを作成（例 `ekiden-timer`）
2. このフォルダの中身をすべてリポジトリ直下へアップ
3. `Settings` → `Pages`
4. `Deploy from a branch` を選び、`main` / `/ (root)` を指定
5. 数分後に表示されたURLを開く

`index.html` をリポジトリの直下に置くのがポイントです。

## CSV形式
テンプレートは管理者画面からダウンロードできます。

```csv
team_no,team_name,runner_name,sex,age_group,leg
1,大豊A,山田 太郎,男,中学生,1
1,大豊A,佐藤 花子,女,一般,2
```

- 1行 = 1区間の走者
- `leg` は 1〜15
- 同じ選手名が複数区間に登場しても可
- 同じチームで同じ `leg` を重複させるとエラー

## Firebaseについて
第1試作は、画面・操作・大会ロジックの確認を優先し、`localStorage` で動かしています。

`firebase-config.js` に Firebase のWebアプリ設定を入れられるようにしてありますが、**複数端末の本番リアルタイム同期はまだ接続していません**。

第2段階では Firebase Realtime Database を接続し、以下を同期する想定です。
- 大会状態（開始前 / 計測中 / 終了）
- エントリー情報
- A/B/C 各計測係の生タイム
- 正式通過タイム
- お知らせ
- 速報順位

# 駅伝大会運営システム 第1段階試作 v0.2

GitHub Pages + Firebase Realtime Database を前提にした、第1段階の試作です。

この版では **「正確に計る」「複数端末で共有する」「不測の事態に備える」** ことを優先しています。
申込フォーム・PDF・表彰状・ファンラン管理などは、次の段階で追加します。

## 第1段階で実装したもの

### 1. ログイン
- 管理者：アクセスコード方式
- 運営計測係：A / B / C を選択し、それぞれ別のアクセスコードでログイン
- チーム計測係：チーム番号 + チーム用アクセスコードでログイン
- 同じ運営計測係、同じチーム計測係を別端末で重複使用しにくくする端末ロック
- ロックは通信断や画面放置を考え、約90秒で失効可能な設計

初期デモコード：
- 管理者 `1234`
- 計測A `1111`
- 計測B `2222`
- 計測C `3333`
- デモチーム1 `1001`、チーム2 `1002` … チーム12 `1012`

管理者画面から管理者・A・B・Cのコードは変更できます。

> 注意：このv0.2のアクセスコードは、誤操作・重複ログイン防止を主目的とする簡易ゲートです。Firebase側の厳密な役割別権限管理はまだ入れていません。本番公開範囲を広げる場合は、後段で権限を強化します。

### 2. 運営側の正式計測
- 全チーム一斉スタート
- A / B / C の3端末から、どのチームでも押せる
- 順位変動に応じて、その場で担当を押し分ける運用に対応
- 同じチームを複数人が押した場合は、2.5秒以内の計測を同一通過として自動統合
- 3名計測：中央値
- 2名計測：平均値
- 1名計測：その値
- 3名・2名・1名のどの方式でも、生の計測値はすべて保持
- 計測値の最大差が0.5秒を超えた場合は管理画面で分かる
- 計測係ごとに直前入力を取り消し可能

### 3. 誤入力の修正
管理者画面の「運営側 生計測ログ」で、
- 間違って押したチーム番号の変更
- 不要な生計測の削除

ができます。

正式通過記録は、
- `HH:MM:SS.cc` 形式で正式時刻を手動修正

できます。

### 4. チーム側バックアップ計測
各チーム1名が、自チームだけを計測できます。

- チーム番号 + チーム用アクセスコードでログイン
- 大きな「通過」ボタンだけを使うシンプルな画面
- 運営計測とは別データとして保存
- **運営側の記録が正式記録**
- 運営側に計測欠落があった場合のみ、管理者が「正式記録に採用」を押して補完可能
- 採用後も「チーム参考記録から採用した」ことが記録上分かる

### 5. Firebase複数端末同期
Firebase設定後は、Realtime Database を使って以下を同期します。
- 大会状態
- チーム
- A/B/Cの生計測
- チーム参考計測
- 修正・補完記録
- お知らせ
- 速報順位
- 端末ロック

Firebase Realtime Database の `.info/serverTimeOffset` を利用し、各端末の時計差を補正して計測時刻を作ります。

### 6. 通信断対策
Firebase使用中でも、書き込み前に端末の `localStorage` に未送信データを保存します。

- 通信断中：端末に記録を残す
- 復旧後：未送信データを再送
- 管理者画面に「未送信データ件数」を表示

ページを閉じる直前の完全保証まではできませんが、単純な「通信が一瞬切れたら記録消失」にならないようにしています。

## Firebaseをまだ設定しない場合

`firebase-config.js` が `null` のままなら、ローカルモードで動きます。

この場合は、同じブラウザ内の確認用です。別のスマホ同士では同期しません。
まず画面・操作を確認してからFirebase設定を行っても構いません。

## Firebaseを有効にする手順

### 1. Firebaseプロジェクト
Firebase Consoleでプロジェクトを作成します。
バスアプリと同じプロジェクトを使うこともできますが、管理上は別プロジェクトに分けても構いません。

### 2. Realtime Database
Realtime Databaseを作成します。
日本から使用するため、選べる場合はアジア圏のロケーションが扱いやすいです。

### 3. Anonymous Authentication
Firebase Authentication → Sign-in method で **Anonymous（匿名）** を有効にします。

このアプリは、参加者閲覧を含むブラウザをFirebase上では匿名認証し、その上にアプリ独自のアクセスコード画面を載せています。

### 4. Database Rules
`database.rules.json` の内容を Realtime Database の Rules に設定してください。

```json
{
  "rules": {
    "ekidenTimerV02": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
```

### 5. Webアプリ設定
Firebaseの「プロジェクトの設定」→「マイアプリ」→ Webアプリから `firebaseConfig` を取得し、`firebase-config.js` の `null` を置き換えます。

特に `databaseURL` が必要です。

## CSV（第2段階までの暫定入力）

```csv
team_no,team_name,team_code,runner_name,sex,age_group,leg
1,大豊A,1001,山田 太郎,男,中学生,1
1,大豊A,1001,佐藤 花子,女,一般,2
```

- 1行 = 1区間
- 15区間
- 同一人物が複数区間を走ってよい
- `team_code` を空欄にすると6桁コードを自動発行
- 第2段階でアプリ内申込フォームに置き換える予定
